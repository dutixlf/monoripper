## Reproduction and root cause

A durable applying operation requests 1 -> 2 replicas. After a controller crash,
startup replays growth from an empty process pool. A dependency permits only one
replica, so the second candidate fails and the first candidate is cleaned up.
`Controller.apply()` restores desired=1 but cannot retain an old worker after a
crash. `initialize()` previously continued with ready=0 and no recovery scheduled.

Regression: `tests/e2e/control-replay-rollback.test.ts`, backed by a real exclusive
file dependency and a validated durable snapshot. RED: desired=1, ready=0.

## Fix

After replay, initialize the actual pool to the current durable desired count,
including a rolled-back count. If even that count cannot start, preserve the
existing cold-start fail-fast behavior. No schema, credential or public API change.
GREEN: failed operation remains queryable, desired=ready=1, HTTP 200, healthy=true.
