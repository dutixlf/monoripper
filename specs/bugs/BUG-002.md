title: Invalid Connection tokens throw and leak an active request lease

## Reproduction and root cause

An HTTP request with `Connection: invalid token, x-remove-me` reaches the gateway.
The forwarding helper passed `invalid token` to `Headers.delete()`, which throws.
The runtime had already incremented `inFlight` outside its fetch error handler.
The request returned 500 and shutdown timed out waiting for a nonexistent body.

Regression: `tests/e2e/http-semantics.test.ts`. RED: HTTP 500 followed by
`SHUTDOWN_TIMEOUT` in the final cleanup hook.

## Fix

Validate Connection-nominated names against the HTTP token grammar. Invalid
options cannot name a real header, so ignore them while removing Connection and
all valid nominated headers. The same helper handles requests and responses.
Prepare request URL, headers and deadline before acquiring the worker lease.
GREEN: HTTP 200, nominated header absent, normal graceful shutdown.
